# Orbit 0.3.0

Orbit 0.3.0 makes migration solving substantially more scalable and brings the previously unreleased 0.2.1 package-management and launcher work into one coordinated release of Orbit, Orbit Launcher, and Orbit GUI.

## Highlights

- Migration alternatives are now represented as independent choice factors instead of eagerly expanding their Cartesian product. The PubGrub fork enumerates Pareto-minimal removal sets, and Orbit asks for each independent choice before computing the final version Pareto front.
- Migration progress is cumulative and throttled, so large searches remain observable without flooding the CLI or GUI event channel.
- `sync` now converges `orbit.toml`, `orbit.lock`, and package groups with the JARs that are actually present, including removal of stale package declarations.
- Packages can be enabled and disabled without losing their configuration. Orbit atomically switches between `.jar` and `.jar.disabled`, and all discovery, installation, migration, and archive paths understand the disabled state.
- `orbit add` receives its constraint explicitly. The GUI exposes the same operation through structured controls instead of adding a hidden default rule.
- The scoped local candidate repository separates provider metadata from parsed JAR metadata, keys artifacts by content hash, and keeps Minecraft and loader scopes isolated. Repeated solving no longer needs to redownload and reparse unchanged candidates.
- Launcher asset indexes are stored by content identity, preventing different Minecraft versions from overwriting a shared mutable index path.
- Microsoft device authentication opens the verification page when possible and always exposes the URL and code for manual completion.
- The GUI now uses a dedicated upgrade icon rather than presenting upgrade as refresh.
- `orbit launch` now wraps Orbit Launcher and injects Orbit's low-overhead Runtime Agent. Mutable
  files follow their last package writer, unowned directories are claimed by their first package writer,
  and growing exceptions are dynamically recompressed without changing per-file ownership; `orbit purge`
  shows one exact plan, removes the logical package from TOML/lock, and deletes only data currently
  owned by that package while preserving deeper current owners. Reads are never observed. Launcher
  remains independent and never calls Orbit.

## Packages

- Windows: `orbit-0.3.0-x86_64.msi` installs Orbit, its Runtime Agent, Orbit Launcher, and Orbit GUI using the selected setup profile.
- Linux: `orbit_0.3.0-1_amd64.deb` carries Orbit and its Agent; `orbit-launcher_0.3.0-1_amd64.deb` and `orbit-gui_0.3.0-1_amd64.deb` remain independently installable.
- `SHA256SUMS` contains checksums for every release package.

The Windows MSI is currently unsigned, so Windows may display an unknown-publisher warning.

## 简体中文

Orbit 0.3.0 重点解决大规模迁移求解的组合爆炸问题，并将此前尚未正式发布的 0.2.1 包管理与启动器改进一并纳入 Orbit、Orbit Launcher 和 Orbit GUI 的统一版本。

### 主要变化

- 迁移方案改为按相互独立的选择因子表达，不再预先展开笛卡尔积。PubGrub fork 原生枚举 Pareto 极小移除集；用户逐因子完成选择后，再统一计算最终版本 Pareto 前沿。
- 迁移进度改为累计且限频的事件，长时间求解既可观察，也不会用海量消息阻塞 CLI 或 GUI。
- `sync` 会让 `orbit.toml`、`orbit.lock`、包组与磁盘上实际存在的 JAR 收敛，并清理已不存在包的陈旧声明。
- 包可在保留配置的前提下启用或禁用。Orbit 原子切换 `.jar` 与 `.jar.disabled`，探测、安装、迁移和归档路径统一理解禁用状态。
- `orbit add` 的约束由调用者显式传入；GUI 使用结构化控件表达同一能力，不再暗中添加默认规则。
- 本地候选版本库将 Provider 元数据与 JAR 解析元数据分离，以内容哈希标识文件，并按 Minecraft 与 Loader 作用域隔离，重复求解无需反复下载和解析未变化的候选。
- Launcher 的资源索引按内容身份保存，避免不同 Minecraft 版本覆盖同一个共享可变路径。
- Microsoft 设备登录会尽量自动打开验证页面，同时始终展示可供手动操作的链接与代码。
- GUI 的升级操作改用独立升级图标，不再与刷新混淆。
- 新增 `orbit launch`，由 Orbit 包装 Launcher 并注入低开销 Runtime Agent。文件归最后成功
  编辑它的包，无主目录由首个写入包认领，排除项增长后按实际文件数动态重压缩且不改变逐文件
  归属；`orbit purge` 会展示一次准确计划，清理逻辑包的 TOML/lock，并按当前递归所有权删除数据，
  同时保留更深层其它所有者；读取完全不监听。
  Launcher 仍保持独立，绝不反向调用 Orbit。

### 安装包

- Windows：`orbit-0.3.0-x86_64.msi`，可按安装配置选择 Orbit（含 Runtime Agent）、Orbit Launcher 与 Orbit GUI。
- Linux：`orbit_0.3.0-1_amd64.deb` 包含 Orbit 与 Agent；另提供 `orbit-launcher_0.3.0-1_amd64.deb` 与 `orbit-gui_0.3.0-1_amd64.deb`。
- `SHA256SUMS` 包含全部发行包的校验值。

Windows MSI 目前未进行代码签名，系统可能显示“未知发布者”提示。
