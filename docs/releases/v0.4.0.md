# Orbit 0.4.0

Orbit 0.4.0 consolidates the native Orbit bundle and Modrinth pack workflows, then hardens the persistence, package-installation, provider, and GUI boundaries used by those workflows.

## Highlights

- A single strict `.orbitbundle` format now carries independent optional Orbit and Launcher projections. Orbit owns packages, package configuration, and package-owned data; Launcher owns Minecraft runtime and game state. Neither component interprets or rewrites the other's projection.
- Native bundle and official `.mrpack` import/export use normalized portable paths, case-insensitive collision checks, exact file inventories, bounded metadata, and content verification. Extraction rejects symbolic-link parents and replaces a destination only after its temporary file passes SHA-256 verification.
- Package mutations are rollback-capable transactions. `install` restores the exact lock realization without solving, while add, fix, constraints, activation, upgrade, and migration keep original JARs recoverable until manifest and lock persistence succeeds.
- Instance mutations are serialized across CLI and GUI processes with a persistent workspace lock. Global instance registration/default changes use a separate lock and rollback both `instances.toml` and `config.toml` if either update fails.
- JAR cache cleaning retains its cross-process lock and cache root, never follows cache symlinks, and cannot split concurrent processes across different lock files.
- Lockfiles, manifests, version-repository records, Launcher artifacts, and archive manifests now validate canonical identities, hashes, filenames, loaders, and portable path uniqueness before use.
- Modrinth and CurseForge clients use structured URL construction, bounded JSON/error bodies, explicit retry classes, redirect restrictions, and sensitive credential headers. CurseForge continues to require an explicitly configured API key.
- Machine progress events now use one snake_case vocabulary across Orbit, audit, Launcher, and GUI. The GUI accepts only the current protocol instead of maintaining legacy event aliases.
- GUI subprocess output and presentation-image downloads are bounded. Remote images are decoded under resource limits, normalized to small local PNGs, and committed atomically.

## Packages

- Windows: `orbit-0.4.0-x86_64.msi` installs Orbit and its Runtime Agent, Orbit Launcher, and Orbit GUI using the selected setup profile.
- Linux: `orbit_0.4.0-1_amd64.deb`, `orbit-launcher_0.4.0-1_amd64.deb`, and `orbit-gui_0.4.0-1_amd64.deb` remain independently installable.
- `SHA256SUMS` contains checksums for every release package.

The Windows MSI is currently unsigned, so Windows may display an unknown-publisher warning.

## 简体中文

Orbit 0.4.0 完成了原生 Orbit 包与 Modrinth 整合包流程的统一，并系统加固这些流程涉及的持久化、包安装、Provider 和 GUI 边界。

### 主要变化

- 统一的严格 `.orbitbundle` 格式包含相互独立、均可省略的 Orbit 与 Launcher 投影。Orbit 只负责模组、模组配置和模组拥有的数据；Launcher 只负责 Minecraft 运行时与游戏状态，双方不解释或重写对方的数据。
- 原生包和官方 `.mrpack` 的导入导出统一执行便携路径、大小写碰撞、精确文件清单、元数据大小和内容哈希校验。解包拒绝符号链接父目录，且只在临时文件通过 SHA-256 后替换目标。
- 包修改改为可回滚事务。`install` 只恢复 lock 的精确实现而不求解；add、fix、约束、启停、升级和迁移会一直保留原 JAR，直到 manifest 与 lock 都持久化成功。
- CLI 与 GUI 对同一实例的修改由持久工作区锁跨进程串行化；全局实例注册和默认实例使用独立锁，并在 `instances.toml` 或 `config.toml` 任一步失败时恢复两者。
- JAR cache 清理保留跨进程锁和 cache 根，不跟随符号链接，也不会让并发进程落入两套互不相识的锁。
- lock、manifest、版本库、Launcher 工件和归档清单会在使用前严格校验规范身份、哈希、文件名、Loader 与跨平台路径唯一性。
- Modrinth 与 CurseForge 客户端采用结构化 URL、受限响应体、明确的重试范围、重定向限制和敏感凭据头；CurseForge 仍必须显式配置 API Key。
- Orbit、audit、Launcher 与 GUI 的机器进度事件统一为 snake_case；GUI 只接受当前协议，不保留旧事件别名。
- GUI 子进程输出和展示图片下载都有资源上限；远端图片在受限解码后规范为小型本地 PNG，再原子写入缓存。

### 安装包

- Windows：`orbit-0.4.0-x86_64.msi`，可按安装配置选择 Orbit（含 Runtime Agent）、Orbit Launcher 与 Orbit GUI。
- Linux：分别提供可独立安装的 `orbit_0.4.0-1_amd64.deb`、`orbit-launcher_0.4.0-1_amd64.deb` 与 `orbit-gui_0.4.0-1_amd64.deb`。
- `SHA256SUMS` 包含全部发行包的校验值。

Windows MSI 目前没有代码签名，系统可能显示“未知发布者”提示。
