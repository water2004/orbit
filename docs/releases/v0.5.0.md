# Orbit 0.5.0

Orbit 0.5.0 adds runtime-aware package data ownership and turns package data management into a transactional, inspectable workflow shared by the CLI and native GUI.

## Runtime-owned files and package reset

- Orbit can now list the files and directory trees owned by each logical mod package. The GUI exposes the same information under **Manage → Files & data** without duplicating ownership logic.
- The Runtime Agent attributes newly created and modified paths to the package that performed the write. Writes delegated through a declared helper dependency are attributed to the calling package, so data written through libraries such as malilib no longer automatically belongs to the library.
- Shared instance roots, Minecraft save roots, and detected server world roots cannot be claimed or recursively removed by one mod. More specific files and mod-created subtrees remain attributable.
- `orbit reset <package>` removes a package's owned data while preserving the package, JARs, constraints, remotes, `orbit.toml`, and `orbit.lock`. Reset and purge stage changes transactionally and restore the original state if an operation fails.
- Old ambiguous helper-owned ledger entries are retired conservatively without deleting physical files. A subsequent observed launch rebuilds precise ownership under the new attribution model.

## Launcher and GUI

- Client instances can configure an explicit game resolution through `orbit-launcher instance resolution set <width> <height>` and clear it with `instance resolution clear`. Launching uses Minecraft's standard `--width` and `--height` arguments; server instances reject the setting.
- Orbit GUI adds native resolution controls and package data reset while remaining a thin shell over the two machine-readable CLIs.
- Ownership, reset, purge, and confirmation responses use typed machine-protocol fields so the GUI does not parse presentation text.

## Performance and reliability

- The common direct-writer path remains allocation-light. A 10,000-write Windows profile measured approximately 1.75% overhead for direct attribution and 6.10% for delegated attribution in an intentionally adverse tiny-overwrite workload; delegated attribution added about 14.9 microseconds per actual write.
- Runtime ownership startup prunes ledger entries for paths that no longer exist, and deletion plans are revalidated before mutation to prevent stale or shared-root claims from becoming destructive operations.

## Packages

- Windows: `orbit-0.5.0-x86_64.msi` installs Orbit and its Runtime Agent, Orbit Launcher, and Orbit GUI using the selected setup profile.
- Linux: `orbit_0.5.0-1_amd64.deb`, `orbit-launcher_0.5.0-1_amd64.deb`, and `orbit-gui_0.5.0-1_amd64.deb` remain independently installable.

The Windows MSI is currently unsigned, so Windows may display an unknown-publisher warning.

## 简体中文

Orbit 0.5.0 新增运行时感知的模组数据所有权，并将数据管理整理为 CLI 与原生 GUI 共用的可检查、事务性流程。

- 现在可以查看每个逻辑模组包拥有的文件和目录树；GUI 在**管理 → 文件与数据**中展示同一份结果。
- Runtime Agent 按实际写入者记录新建和修改的路径。经声明的公共依赖代理写入时，文件归调用方而不是公共库，因此 Masa 系模组通过 malilib 写入的数据会归相应模组。
- 实例共享根目录、Minecraft 存档根目录及识别出的服务端世界根目录不会被单个模组占有或递归删除，更具体的文件和模组创建的子树仍可正常归属。
- 新增 `orbit reset <package>`：删除包拥有的数据，但保留包本体、JAR、约束、远端、`orbit.toml` 和 `orbit.lock`。reset 与 purge 均采用事务性暂存，失败时恢复原状。
- 旧账本中无法可靠判断的公共库归属会被保守移除，但不会删除实际文件；后续受观察的启动会按新模型重新建立精确归属。
- Launcher 新增客户端分辨率设置和清除命令，GUI 提供对应原生控件；服务端实例会拒绝客户端分辨率设置。
- 在刻意放大相对开销的极小文件覆盖压测中，直接归属开销约 1.75%，代理归属约 6.10%，代理归属每次实际写入增加约 14.9 微秒。

Windows MSI 当前没有代码签名，系统可能显示“未知发布者”提示。
