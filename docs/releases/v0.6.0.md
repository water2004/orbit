# Orbit 0.6.0

Orbit 0.6.0 makes runtime-owned mod data stable across JAR replacement and includes the Launcher and GUI reliability work prepared after 0.5.0.

## Highlights

- Runtime attribution still identifies executing code with exact top-level and nested JAR hashes, but Agent snapshots and `ownership.toml` now persist the stable logical mod ID. `sync`, upgrades, and same-version artifact replacements no longer make existing ownership records disappear.
- Existing schema 3 ownership ledgers are converted once. Orbit uses the current lock first and, when a JAR was already replaced, the last verified Agent context to recover the old artifact-to-package relation. Ambiguous records are left unowned rather than guessed; no physical user data is deleted.
- Portable Orbit exports and migrations now include only instance-relative owned data. System temporary files and other `external` paths remain visible to local `ownership`, `reset`, and `purge`, but never enter a bundle or destination ledger.
- The Runtime Agent context/snapshot protocol is version 4. Artifact hashes remain on the hot attribution path; conversion to logical package IDs happens only while publishing a snapshot, preserving the low-overhead I/O path.
- Orbit Launcher resolves the official Minecraft logging configuration from the shared repository and passes the instance directory through the standard game-directory argument instead of rewriting the logging path.
- The GUI ownership panel refreshes the matching package request when **Manage → Files & data** opens, exposes retry/refresh states, and cannot be overwritten by a stale response.

## Packages

- Windows: `orbit-0.6.0-x86_64.msi` provides the selectable Orbit, Orbit + Launcher, and full Orbit + Launcher + GUI installation profiles.
- Linux: `orbit_0.6.0-1_amd64.deb`, `orbit-launcher_0.6.0-1_amd64.deb`, and `orbit-gui_0.6.0-1_amd64.deb` remain independently installable.

# Orbit 0.6.0（简体中文）

Orbit 0.6.0 让模组运行时数据归属在 JAR 替换后仍保持稳定，并纳入 0.5.0 之后完成的 Launcher 与 GUI 可靠性改进。

## 重点改进

- 运行时仍用顶层/嵌套 JAR 的精确哈希识别正在执行的代码，但 Agent snapshot 与 `ownership.toml` 改为持久化稳定逻辑 mod ID。`sync`、升级或同版本不同实现替换 JAR 后，已有归属记录不会再消失。
- schema 3 旧账本只进行一次转换。Orbit 优先使用当前 lock；若 JAR 已被替换，则从最后一次经过验证的 Agent context 恢复旧 artifact 到逻辑包的关系。歧义记录宁可转为无主也不猜测，且不会删除任何物理用户数据。
- Orbit 自有格式导出和迁移只携带实例内相对路径。系统临时文件等 `external` 路径仍会出现在源实例的 `ownership`、`reset`、`purge` 中，但绝不会写入组合包或目标账本。
- Runtime Agent 上下文/snapshot 协议升级到 v4。性能敏感的运行期归因仍使用 artifact 哈希，只在发布 snapshot 的冷路径转换为逻辑包 ID。
- Orbit Launcher 从共享仓库解析 Minecraft 官方日志配置，并通过标准游戏目录参数传递实例目录，不再改写日志配置路径。
- GUI 的**管理 → 文件与数据**会刷新当前包的归属结果，提供重试/刷新状态，过期响应也不能覆盖当前包。

## 安装包

- Windows：`orbit-0.6.0-x86_64.msi` 继续提供仅 Orbit、Orbit + Launcher、Orbit + Launcher + GUI 三种安装组合。
- Linux：`orbit_0.6.0-1_amd64.deb`、`orbit-launcher_0.6.0-1_amd64.deb`、`orbit-gui_0.6.0-1_amd64.deb` 可独立安装。
